# V2.2 Milestone 1 Product Requirements Document

Status: draft
Source: docs/planning/v2/v2.2-creative-application-generation-spec.md

## Goal

Create the richer application context layer needed for later creative generation: improve profile import coverage and generate a per-application candidate fit brief from the approved profile and job posting, without changing draft generation behavior.

## Problem Statement

Manual QA showed that the application draft can become narrow even when the model is capable of richer reasoning. The app currently compresses the candidate into a small set of approved evidence matches before generation. If the approved facts are too few, too broad, or too project-specific, the final draft repeats those facts and misses the broader CV story.

The first V2.2 milestone should fix the context starvation problem before changing final writing behavior. The app needs a structured way to understand the candidate's skills, competencies, projects, education, work history, transferable strengths, and risk areas for each application, but the visible result is limited to better approved profile facts and a compact per-application fit brief.

## Solution

Milestone 1 expands the profile extraction and preparation context only.

Profile import should extract more granular and reviewable facts from a CV, including technical skills, competencies, projects, education, work history, business experience, communication strengths, languages, domains, allowed claims, and risky claims to avoid.

Application preparation should generate and store a `CandidateFitBrief` for the current application. `CandidateFitBrief` is not a new domain concept; it is an AI workflow artifact stored as the latest workflow state on `JobApplication`. The fit brief is writing context, not proof by itself. It summarizes the approved profile against the job posting and maps concrete items back to supporting approved profile fact ids for traceability. Those profile fact references do not bypass per-application evidence review.

Hard rule: `CandidateFitBrief.profileFactIds` are traceability only. They must never be treated as approved evidence for final claims.

## User Stories

1. As a job applicant, I want CV import to extract competencies as well as technical skills, so that my profile reflects more than a tool list.
2. As a job applicant, I want projects, education, work history, business experience, languages, and transferable strengths extracted into reviewable facts, so that applications can use my full background.
3. As a job applicant, I want imported facts to remain draft until approved, so that AI extraction cannot silently support claims.
4. As a job applicant, I want enough granular facts to approve a useful evidence library, so that the app does not stretch one broad fact across many job requirements.
5. As a job applicant, I want the app to summarize my fit for a specific job, so that I can see whether it understood my broader relevance.
6. As a job applicant, I want the fit summary to show skills, competencies, projects, transferable strengths, and risk notes, so that I can judge whether the application context is strong enough.
7. As a job applicant, I want concrete fit-brief items mapped to approved profile facts, so that creative writing remains traceable.
8. As a job applicant, I want weak or unsupported themes called out as risks, so that the app does not overstate my experience.
9. As a developer, I want a strict JSON contract for candidate fit brief generation, so that local model output can be validated and repaired.
10. As a developer, I want the fit brief stored as latest application workflow state, so that evidence matching, strategy, draft generation, and audit can use the same context.
11. As a developer, I want provider failures during fit brief generation to preserve prior stable application state, so that preparation remains safe.
12. As a developer, I want fake AI to return deterministic fit brief artifacts, so that workflow tests and demos remain reliable.

## Implementation Decisions

- Revise `assisted-profile-import.md` so full CV import no longer prefers only `1-5` high-signal facts.
- Extract reviewable draft facts for skills, tools, projects, work history, education, languages, competencies, transferable strengths, allowed claims, and forbidden claims.
- Keep imported facts in `Draft` status until user approval.
- Reuse the existing profile fact trust boundary; do not introduce automatic approval.
- Add a `CandidateFitBrief` AI workflow artifact to the latest workflow state stored on `JobApplication`; do not introduce it as an independent domain concept.
- Add an AI provider method for candidate fit brief generation.
- Candidate fit brief input should include application metadata, job posting or job signals, selected language, tone preference where available, and all approved profile facts.
- Candidate fit brief output should include candidate summary, skill groups, competencies, relevant projects, transferable strengths, and risk notes.
- Concrete fit brief items should include supporting approved profile fact ids for traceability only, not as final proof.
- Candidate fit brief output must be clearly treated as writing context. `CandidateFitBrief.profileFactIds` must not be considered approved evidence. Concrete final-draft claims still require per-application approved evidence or approved job-local custom facts.
- Fit brief generation should run as part of `Prepare application` after job analysis and before or alongside evidence matching.
- If fit brief generation fails, preserve prior stable state and return a plain provider or validation error.
- Record an `AiRun` step for `CandidateFitBrief`.
- Show a compact fit brief summary in the application detail page after preparation.
- Do not change draft generation prompts, inputs, behavior, or claim-audit rules in this milestone except for compile-time contract updates required by the new latest-state artifact.

## Testing Decisions

- Test public API/workflow behavior rather than private parser details.
- Cover CV import producing multiple draft fact types from a rich CV.
- Cover imported competencies and transferable strengths remaining unusable for matching until approved.
- Cover approving imported facts and using them in a candidate fit brief.
- Cover candidate fit brief generation receiving all approved profile facts, not only matched evidence.
- Cover candidate fit brief output validation, including invalid ids and missing arrays.
- Cover candidate fit brief profile fact ids remaining traceability-only and not becoming approved evidence.
- Cover provider unavailable and malformed JSON preserving prior stable state.
- Cover fake provider deterministic candidate fit brief output.
- Cover frontend rendering of candidate summary, skill groups, competencies, projects, and risk notes where existing test seams support it.

## Out of Scope

- Evidence quality labels.
- Application strategy generation.
- Final draft prompt rewrite.
- Claim audit changes beyond any compile-time contract updates.
- Any draft generation behavior changes.
- Editable candidate fit brief.
- Full profile fact revision history.
- Automatic profile fact approval.
- New document formats beyond existing supported CV import.
- Model selection changes.

## Further Notes

This milestone should make the app understand the candidate more like the successful direct-chat baseline: first extract the broader profile, then reason about how that profile fits the job. It should not try to solve final prose quality yet. The outcome is a richer, traceable context layer that later milestones can use for better matching and writing.
