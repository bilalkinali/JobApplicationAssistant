# V2.1 Assisted Profile Import PRD

Status: ready-for-agent
Source: User feedback on 2026-05-15 after local AI workflow testing

## Problem Statement

The current trust workflow depends on approved profile facts, but manually creating a useful profile is too much upfront work. In practice, the user may start with only one skill or a small set of facts because entering technical skills, work history, projects, tools, domains, achievements, and allowed claims by hand is tedious.

That creates a weak first-run experience: the app can analyze a job and run the workflow, but it cannot match much evidence or generate strong application text until the user's profile contains enough structured facts. V2.1 should make profile setup feel assistant-led by letting the user upload or paste a CV and have local AI extract as much useful, reviewable profile information as possible.

## Solution

Add an assisted profile import workflow that accepts CV files and pasted profile text, extracts draft profile facts through the configured AI provider, and saves them for user review. The import should identify technical skills, tools, platforms, projects, job history, responsibilities, achievements, domains, education, certifications, languages, and other reusable application evidence.

Imported facts must remain untrusted until the user reviews and approves them. The review experience should make it fast to approve, edit, merge, split, archive, or reject draft facts. Once approved, imported facts become normal profile facts and can support evidence matching, draft generation, and claim audit.

The feature should prioritize UX over perfect parsing: the user's first valuable experience should be uploading a CV, reviewing a well-organized queue, and quickly turning it into a strong reusable profile.

## User Stories

1. As a job applicant, I want to upload my CV, so that the app can build my profile without me manually entering every skill and experience.
2. As a job applicant, I want to paste raw CV text when file upload is inconvenient, so that I can still import my background quickly.
3. As a job applicant, I want the app to extract technical skills, so that job matching can find relevant evidence from my background.
4. As a job applicant, I want the app to extract tools, frameworks, platforms, and programming languages, so that my profile reflects the technologies I can credibly mention.
5. As a job applicant, I want the app to extract work experience, projects, responsibilities, and achievements, so that generated applications can use concrete evidence.
6. As a job applicant, I want the app to extract education, certifications, languages, and domain experience where present, so that my profile is more complete.
7. As a job applicant, I want imported facts saved as draft facts first, so that unreviewed AI extraction cannot support application claims.
8. As a job applicant, I want a review queue for imported facts, so that I can quickly approve, edit, archive, reject, merge, or split them.
9. As a job applicant, I want duplicate or overlapping facts detected, so that importing a CV does not clutter my profile.
10. As a job applicant, I want extracted facts grouped by type or theme, so that review does not feel like a long random list.
11. As a job applicant, I want each draft fact to show source context from the CV, so that I can verify why the AI extracted it.
12. As a job applicant, I want the app to suggest allowed claims from my CV, so that generated text can make strong but honest statements.
13. As a job applicant, I want the app to avoid inventing claims not present in my CV, so that my profile remains trustworthy.
14. As a job applicant, I want approved imported facts to become normal reusable profile facts, so that they work with the existing job workflow.
15. As a job applicant, I want the import result to make the next job application stronger immediately, so that profile setup feels essential rather than administrative.
16. As a job applicant, I want provider failures during import to preserve any existing profile state, so that a bad AI response cannot damage my profile.
17. As a job applicant, I want clear import diagnostics if local AI fails, so that I know whether to fix LM Studio, model configuration, or input format.
18. As a developer, I want CV import to reuse the existing AI provider abstraction, so that Fake, Ollama, and OpenAI-compatible local paths stay explicit.
19. As a developer, I want imported draft facts to use the existing profile fact trust boundary, so that only approved facts can support matching and generation.
20. As a developer, I want the extraction parser to validate structured AI output, so that malformed or incomplete provider output fails gracefully.
21. As a developer, I want source snapshots preserved where useful, so that later audits can explain where imported facts came from.
22. As a developer, I want the importer to be testable without file parsing or provider calls tangled into profile persistence, so that extraction and review behavior can be locked down.

## Implementation Decisions

- Treat V2.1 as the profile setup and profile enrichment release after the V2.0 assistant-led application workflow is stable.
- Support both file upload and pasted text import.
- File upload should initially target common CV formats that are practical in the local app context, with PDF and DOCX as the highest-value formats.
- Convert uploaded files into text before AI extraction; keep document layout editing and CV formatting out of scope.
- Add an AI operation for profile import extraction behind the existing provider abstraction.
- The extraction output should produce draft profile facts, not approved facts.
- Extract reusable evidence into the existing profile fact concepts where possible: title, type, summary, fact items, technologies, allowed claims, forbidden claims, source document references, and original imported snapshot.
- Preserve the trust boundary: imported facts cannot support evidence matching, draft generation, or claim audit until approved by the user.
- Add or extend profile APIs for creating an import session, listing draft imported facts, reviewing individual facts, and bulk approving or archiving selected facts.
- Add duplicate detection against existing profile facts and within the import batch.
- Prefer a review queue that supports quick decisions over a fully manual editor-first flow.
- Keep imported source context visible enough for user verification, but do not expose large raw documents everywhere in the UI.
- Record AI import attempts with useful provider diagnostics and failure information.
- Keep raw payload storage governed by the existing `StoreRawPayloads` setting.
- Do not silently fall back from a configured real provider to Fake AI during import.
- Fake AI may return deterministic extraction fixtures for tests and demos, but it must remain labeled as deterministic demo/test mode.
- Consider a deep module boundary around CV text extraction plus AI extraction normalization, separate from profile persistence and review decisions.

## Testing Decisions

- Test public behavior through profile import APIs and profile fact review flows, not private parser details.
- Cover successful pasted text import creating draft profile facts that cannot support matching until approved.
- Cover successful file-text import at the service boundary without requiring brittle binary fixture parsing in every workflow test.
- Cover approving imported draft facts and then using them as normal approved profile facts in evidence matching.
- Cover duplicate detection against existing profile facts and within one import batch.
- Cover malformed AI output, empty extraction output, provider timeout, unreachable endpoint, non-success response, and invalid JSON preserving existing profile state.
- Cover `StoreRawPayloads` behavior for import failures consistently with other AI operations.
- Cover Fake AI deterministic import behavior separately from real provider behavior.
- Cover UI review queue behavior for approve, edit, archive, reject, and bulk actions where frontend test seams exist.

## Out of Scope

- CV layout editing or preserving a designed CV layout.
- Generating a new CV document.
- Applying to jobs directly from a CV upload without user review.
- Automatically approving imported facts.
- Full profile fact revision history.
- Multi-user document storage and permissions.
- Cloud OCR or external document-processing services.
- Provider settings UI beyond existing diagnostics and configuration.

## Further Notes

This is essential to the product UX because the application workflow is only as good as the profile evidence library. Local AI can now analyze job postings, but the user should not have to manually bootstrap a rich profile before the app becomes useful. V2.1 should make the first serious setup path: upload CV, review extracted facts, approve the strong ones, then use them immediately in the application workflow.
